No new equation is false. `bend LAWS.bend --check-only` reports 53 unproven laws, one per law, and `bend test/spot.bend` passes. The problems are a law that cannot be rewritten, and three facts a packed-bytes proof still cannot reach.

1. **`byte_pack4` — should fix.** The equation is true for `j < 4` and each `bi < 256`: `List.get` on `[b0, b1, b2, b3]` is `Some{bj}`, and byte `j` of `pack4` is `bj`. It cannot be used. The conclusion is an equality of `Maybe`s naming `List.get`, and this package has no `List.get` or `Some`-injectivity law, so it does not rewrite to `D.byte(D.pack4(b0, b1, b2, b3), j) == bj`. The numeric route is also blocked: `to_nat_pack4` plus `to_nat_byte` gives `mod(div(b0 + b1·2^8 + b2·2^16 + b3·2^24, 2^(8j)), 256)`, and there is no `mod(x + m·k, m) = mod(x, m)` law. Add a `nth4` in `defs.bend` and state `{D.byte(D.pack4(b0, b1, b2, b3), j) == D.nth4(j, b0, b1, b2, b3) : U32}` under the same hypotheses. `j` has to stay a parameter: the read index is `i & 3`, not a literal `0`, `1`, `2`, or `3`.

2. **Shifted copy — should fix.** Aligned get and set are covered (`byte`, `put_byte`, `pack4_bytes`, `byte_put_same`, `byte_put_other`). An unaligned word is not. Copying four bytes starting at byte offset `k ∈ {1, 2, 3}` from a lower word `lo` and the next word `hi` is `U32.or(U32.shrn(lo, s), U32.shln(hi, Nat.sub(32n, s)))` with `s = 8k`. Example: `lo = 0x04030201`, `hi = 0x08070605`, `s = 8` gives `(lo >> 8) | (hi << 24) = 0x05040302`, bytes `02, 03, 04, 05`. In numbers that is `floor(n(lo) / 2^s) + (n(hi) mod 2^s) · 2^(32−s)`. `to_nat_or_split` does not apply: the high piece is `shln(hi, 32−s)`, and nothing proves `n(shln(a, k))` is divisible by `2^k` (`(n(a)·2^k) mod 2^32` needs Nat lemmas that are not here). The identity holds for every `s`, using truncating `Nat.sub`: at `s = 0` it is `lo`, at `s ≥ 32` it is `hi` (`shrn` is `0`, `shln(hi, 0) = hi`).

3. **Zero-byte test — should fix.** Nothing states `zb(v) = (v − 0x01010101) & ~v & 0x80808080`. It belongs next to `pack4`: `0x01010101` is `pack4(1, 1, 1, 1)` and `0x80808080` is `pack4(128, 128, 128, 128)`. The true law is word-level: `U32.is_eq(zb(v), 0)` if and only if all four of `byte(v, 0)` … `byte(v, 3)` are nonzero. Borrow explains it. Subtracting `1` from byte `0` sets that byte's bit 7 exactly when the byte was `0`, and a borrow propagates only out of a `0` (or out of a `0` or `1` once a borrow has started). So a nonzero `zb(v)` means some byte is `0`, and a word with no zero byte produces no borrow and `zb(v) = 0`. Do not state the per-byte version. For `v = 0x02020100` (bytes `00, 01, 02, 02`), `v − 0x01010101 = 0x0100FFFF`, and `zb(v) = 0x00008080`: bit 7 of byte `1` is set even though that byte is `0x01`.

4. **Word index in range — should fix.** `Array.get` takes a `U32`. The read is `byte(get(words, shrn(i, 2)), to_nat(and(i, 3)))`. `to_nat_shrn` and `to_nat_and_mask` give `n(i >> 2) = floor(n(i) / 4)` and `n(i & 3) = n(i) mod 4`, and `nat_div_mod` puts them back together. Nothing gives `i >> 2 < w` from `i` belonging to `w` words. Add:
   - `n(i) < 4·n(w)` ⇒ `{U32.is_lt(U32.shrn(i, 2n), w) == True{}}`. Checked: `w = 1`, `i = 3` (`3 < 4`, `shrn = 0`); `w = 2^30`, `i = 2^32−1` (`2^32−1 < 4·2^30`, `shrn = 2^30−1`).
   - `{Nat.div(Nat.mul(a, b), b) == a}` only for `b > 0`, so a full-word length `4·w` shifts back to `w`. At `b = 0`, `a = 1`: `Nat.div(0, 0) = 0 ≠ 1`.
   State the bound with `Nat.mul` of the two `to_nat`s. `U32.mul(w, 4)` is the wrong hypothesis: `U32.mul(2^30, 4) = 0`, and no `i` is `< 0`.

5. **`to_nat_and_mask` — minor.** The equation is true. For `k ≤ 32`, `n(m) = 2^k − 1` is the low-`k` mask (`k = 0` forces `m = 0`, and both sides are `0`; `k = 32` is all-ones). For `k > 32`, `2^k − 1` is not a word value, so the hypothesis never holds. The comment says that from 32 up the mask is all-ones. All-ones stands for `2^32 − 1`, not for `2^33 − 1`. Say that `k > 32` is excluded by the hypothesis, and that `k = 32` is the all-ones word.

6. **`pack4`, `put_byte` — minor.** The formulas match the comments after the colon, and the laws that assume `bi < 256` and `j < 4` are true. The prose before the colon omits those conditions. `pack4(256, 0, 0, 0) = 256`, whose bytes are `0, 1, 0, 0`, not `256, 0, 0, 0`. `put_byte(0, 0n, 256) = 256`, so byte `0` is `0`. `put_byte(0, 4n, 1) = 0`, because a shift of `32` is `0`. `byte_put_same` correctly refuses both: drop `j < 4` and `byte(put_byte(0, 4n, 1), 4n) = 0 ≠ 1`.
